# 90-exceptions

## 目的
通常フローから外れる例外時に、判断を属人化させず、事故防止を優先して扱うための文書です。

## 例外運用の原則
- 例外は通常化しない
- 迷ったら高リスク変更として扱う
- 例外適用時は、何を省略し、何を代替したかを明示する
- 省略した確認は、後追いで補完する前提にする

## 例外の例
- 緊急修正で通常レビューの時間が取れない
- 本番障害対応で最低限の差分だけ先に入れる
- 一時的な設定変更が必要
- 他チーム依存で一部確認が遅れる

## 例外時の最低条件
- `00-entry.md` は必ず読む
- 高リスク判定は必ず行う
- 省略した工程を明示する
- 承認者が例外として扱うことを認識している
- 事後確認の担当と期限を決める

## 禁止事項
- 例外を理由に高リスク変更を通常変更扱いしない
- 例外を口頭だけで処理しない
- 事後確認なしで完了扱いにしない
