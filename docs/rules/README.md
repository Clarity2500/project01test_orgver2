# 人間用ルール読解タイミング一覧表

## 目的
この一覧表は、Cursor の AI エージェントを用いた開発において、  
**人間がどのタイミングで、どのルールを読むべきか** を固定し、以下を実現するためのものです。

- 事故防止
- 属人化防止
- 新メンバーでも迷わない運用
- AI エージェントの暴走防止
- 高リスク変更時の人間確認漏れ防止

---

## 基本方針
人間用ルールは、毎回すべてを読ませない。  
**入口 → 工程 → 高リスク追加 → 詳細** の順に読む Bootstrap 型構造とする。

### ルール階層
- **L0: 入口**
  - 全員が最初に読む
  - 今回の変更の種類、役割、次に読む文書を決める
- **L1: 工程カード**
  - 工程ごとに読む短いルール
- **L2: 高リスク追加パック**
  - 高リスク変更のときだけ追加で読む
- **L3: 詳細**
  - 例外、用語、補足、背景説明

---

## 読む量の上限
ルールが肥大化しないよう、以下を上限とする。

- **L0 は 1 ページ以内**
- **各 L1 は 1 ページ以内**
- **各 L2 は 1 ページ以内**
- 詳細説明はすべて L3 に逃がす
- 1 回の着手で読む対象は **最大 3 枚**
  - L0
  - 該当する L1
  - 必要なら該当する L2

---

## 固定ルール
1. **L0 を読まずに作業を開始してはいけない**
2. **高リスク判定は勘で行わず、定義済みの分類表で行う**
3. **各役割は、自分に必要なカードだけで最低限判断できる構造にする**
4. **レビュー担当と PR 承認者の責任を分ける**
5. **承認後に差分が変わった場合は、再確認・再承認を前提とする**
6. **認証・認可・権限・個人情報・秘密情報を含む変更は必ず高リスク変更として扱う**
7. **AI が提案した内容でも、人間が読むべきルールと承認境界は同一とする**

---

## 高リスク変更の定義
以下のいずれかに該当する変更は、高リスク変更とする。

- 認証
- 認可
- 権限変更
- セッション管理
- DB スキーマ変更
- 外部 API / 外部通信追加・変更
- 個人情報
- 秘密情報
- ログ出力方針変更
- 依存関係追加・更新
- 本番設定変更
- セキュリティ設定変更
